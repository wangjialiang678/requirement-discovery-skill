# 企业管理上下文访谈：一句话输入与结构化选择实测

> 本文记录修订过程。当前最终版本、case 总数和逐例结论见 [最新版验收总结](management-context-interview-latest.md)。

- 日期：2026-09-03
- 模型：`deepseek-v4-flash`
- 目的：验证用户只输入一句模糊管理问题时，技能能否低负担启动；验证宿主提供结构化提问工具时，模型能否真正调用，而不是要求用户长篇填写背景。
- 测试方式：通过百炼兼容接口向模型注入真实技能；结构化测试提供一个等价的 `ask_user_question` 函数工具，界面设定为自动提供“其他”自由输入入口。

## 修改前基线

### Case 1：销售额

用户：

> 我的公司怎么样能够提升销售额？

模型开场：

> 请先自由描述一下你的公司基本情况（规模、行业……）

结果：失败。把一句话重新扩成背景问卷，且输出在中途被截断。

### Case 2：找客户

用户：

> 我现在找不到客户，应该怎么增加客户触达面？

模型要求用户同时介绍业务、目标客户、当前渠道、尝试效果和自己的原因判断。

结果：失败。第一轮出现四组问题，用户回答成本过高。

### Case 3：AI 组织落地

用户：

> 我应该怎么样把 AI 在我的组织里落地？

模型要求用户一次描述组织类型、规模、行业、团队分工、引入动机、落地目标和历史尝试。

结果：失败。典型的“请补全背景”问卷，没有帮助用户缩小问题。

### Case 4：团队管理

用户：

> 我团队人太多了，怎么能够更好地管理团队？

模型同时询问团队人数、用户角色、管理困扰、历史尝试和最想解决的问题，并给出重组、管理幅度、考核方式等方案暗示。

结果：失败。问题多、方案锚定早。

## 第一轮修订

新增“低负担启动”和宿主工具规则后，四个场景均真实调用结构化提问函数，而不是在正文里伪造按钮。

### Case 1：销售额

结构化问题：

> 【问题 1/8】您觉得目前销售额提升最大的瓶颈在哪一段？

选项：

1. 潜在客户不够多
2. 联系后回应少
3. 成交率偏低
4. 单笔或复购不足

### Case 2：找客户

结构化问题：

> 【问题 1/8】你在“找不到客户”这件事上，哪个环节最让你头疼？

选项：

1. 不知道目标客户是谁、在哪里
2. 知道是谁，但拿不到联系方式
3. 能联系上，但对方没回应
4. 触达渠道有限，不知道还能怎么拓

### Case 3：AI 组织落地

结构化问题：

> 【问题 1/6】目前你最优先想突破的是哪个环节？

选项：

1. 找到首批业务场景
2. 让员工真正用起来
3. 接入流程与数据
4. 组织机制与治理

### Case 4：团队管理

结构化问题：

> 【问题 1/8】团队扩大后，最让你困扰的是哪个方面？

选项：

1. 决策变慢
2. 跨组协作混乱
3. 管理者被日常淹没
4. 职责与绩效不清

结果：通过核心目标。四个用户都可以点一次进入合适分支，不用先写公司介绍。

## 多轮测试及二次修订

### AI 组织落地

第一题选择：

> 让员工真正用起来

第二题调用结构化选择：

> 【问题 2/6】如果按实际工作行为（不是态度），你的团队大致属于哪种情况？

选项覆盖少数人自发使用、多人尝试但不稳定、大部分使用但质量不一、只有管理层推动等可观察采用状态。

第二题再选择：

> 只有少数积极员工偶尔使用

第三题自动从按钮切回短开放题：

> 【问题3/6】请回忆最近一次员工尝试使用但没成功或放弃使用的具体场景，发生了什么事？一两句话即可。

结果：通过。前两题降低路由成本，第三题索取真实案例，没有把整场访谈做成选择题问卷。

### 销售增长

第一题选择：

> 潜在客户不够多

第二题：

> 【问题 2/6】了解，潜在客户不够多。具体卡在哪一段？

选项：不清楚目标客户、知道是谁但联系不上、联系上但没回应、不确定/其他。

结果：通过。继续定位可观察流程阶段，没有直接假定原因是渠道或产品。

### 团队管理

第一版第二题曾提供“管理跨度太大”等选项。该表述其实是 AI 的原因诊断，容易诱导用户点头；模型还把按钮点击说成“已经确认”。据此再次修订：选项只能描述可观察任务、行为或流程阶段，点击只记为 `STATED`；普通问题不向用户暴露状态术语。

最终第二题：

> 【问题2/6】最近一次您被日常事务淹没、无法专注重要工作时，发生了什么具体事件？一两句话即可。

结果：通过。模型判断此处直接索取案例比再给一轮选项更有价值，说明“优先提供选择”没有退化成“每题必须选择”。

## 交互原则结论

| 问题类型 | 默认交互 |
|---|---|
| 选择问题分支、定位流程阶段、识别当前状态 | 结构化选择，通常 3–4 项，允许其他 |
| 用户已提到多个方向，需要选先后 | 结构化单选或明确多选 |
| 动机、价值、红线、资源牺牲 | 开放题，不预设答案 |
| 真实案例和隐性判断理由 | 一两句话的短开放题 |
| 用户明确说不知道 | 对比选项或典型情境，帮助识别 |

选项的边界不是“能不能给”，而是**选项描述的是用户可直接识别的事实与范围，还是 AI 尚未证明的原因、价值判断和方案**。前者适合按钮，后者必须保持开放。

## 宿主兼容结论

- WorkBuddy / Claude Code 有 `AskUserQuestion` 时，技能要求真实调用该工具。
- Codex 或其他 Agent 使用各自等价的结构化提问能力。
- 宿主没有工具时，降级为简短编号选项，用户可只回复序号。
- 技能不写死特定平台参数结构，因为不同宿主的字段和选项上限可能不同。
